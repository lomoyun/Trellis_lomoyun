# TLL 简单任务委派与主 Agent 验收规则

## 目标与边界

将已确认的规则写入 TLL 共享入口，通过 `tll init/update` 生成到项目 `AGENTS.md`，并由现有只读 hook 复用。

规则面向所有支持且允许原生 subagent 的宿主。TLL 提供行为指令和结果记录；派发、通知、等待与取消由宿主承担。本次不新增调度器、后台监听、CLI 命令、配置项或强制验收门禁。

## 实施步骤

**S1：记录任务并完善共享入口**

恢复写模式后创建 quick Task `simple-subagent-delegation`，记录目标、验收及本计划。修改 `packages/cli/src/platforms.ts` 的共享入口，保留一个主 Agent 负责整体交付，并加入：

- 简单任务必须同时满足：目标明确、范围可界定、依赖就绪、影响可控、验收可执行。
- 满足上述条件且委派有实际收益时，使用宿主原生 subagent。文件数、代码行数和预计耗时仅作参考。
- 子 Agent 可以自行阅读相关代码、选择局部方案、实现和自测。
- 默认最多同时运行两个子 Agent，不允许递归委派；遵守更严格的宿主限制及用户要求。
- 不支持原生委派时由主 Agent 完成，不通过额外 CLI 进程模拟。
- 同一交付目标内的委派属于既有 Task 的 Plan 步骤，不自动创建子 Task。

**S2：明确交付与验收协议**

在同一入口内规定：

- 主 Agent 派发时说明 Task/步骤、目标、修改范围、必要依据、验收方式及代码基线。
- 并行实现分配不重叠的写入范围；主 Agent 不同时修改子 Agent 负责的文件。发生范围或依赖冲突时，暂停受影响部分并重新分配。
- 子 Agent 返回改动说明、文件或产物、实际验证及其对应版本、未完成事项；需要改变业务规则、公共接口或扩大范围时回报主 Agent。
- 子 Agent 不执行通用入口中的任务登记、会话绑定、Plan/Trace 更新或 Task 完成流程，也不自行提交、推送。
- 主 Agent 利用宿主通知或等待能力接收结果，检查实际 diff、需求符合度、验证证据和集成影响。
- 同一代码和环境下可核实的验证证据可以复用；发生变化或证据不足时补跑相关检查。
- 验收结论分为通过、返工、接管或重新拆分。子 Agent 结束不代表验收通过，单个步骤通过不代表整个 Task 完成。
- 主 Agent 使用现有 checkpoint/evidence 记录委派及验收结果，不新增事件类型或持久化 schema。

**S3：更新说明与本仓库入口**

同步使用说明，明确规则属于指令层、checkpoint 不执行检查、finish 尚无强制验收门禁。

构建后先运行本仓库的 `tll update --dry-run`，确认范围后通过现有更新流程刷新受管入口和模板清单。保留受管块外内容；遇到用户修改冲突时不强制覆盖。其他项目不批量更新。

## 验证与验收

- 检查生成的入口完整表达简单任务标准、子 Agent 自主范围、角色边界和主 Agent 验收责任。
- 扩展必要的入口集成覆盖：新初始化、旧受管块安全升级、用户修改冲突、重复更新幂等，以及各现有 hook 复用相同入口且不写入状态。
- 顺序执行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm smoke:pack`；验证打包后的 CLI 生成新规则，保持现有文件数量与兼容性约束。
- 在当前宿主的隔离临时样例中验证一次真实委派：子 Agent 完成局部实现和自测，主 Agent 收到结果、检查实际改动并给出验收结论。子 Agent 不修改 TLL 任务记录。
- 软件回归与真实宿主结果分别记录；未运行的其他宿主不宣称已验收。若当前宿主实测受阻，明确保留该未验证项。
- 必要验收完成后，由主 Agent记录 checkpoint 并结束本 Task。
